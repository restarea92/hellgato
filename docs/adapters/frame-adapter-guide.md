# Full-frame adapter development

An adapter is an independent executable registered as an `.hga` package. Adding
one does not require changes to the Node core or Rust GUI. The core owns Stream
Deck sessions, virtual identities, composition and scheduling. The adapter owns
discovery, firmware reporting, physical layout, input translation and USB output.

Start with `adapters/simulator/worker.mjs`, or `adapters/mirabox-rust` for a Rust
implementation wrapping a manufacturer DLL. Other implementation languages are
supported. A manufacturer SDK is optional; a documented USB protocol can be
implemented directly. Bundled DLLs need redistribution permission and all runtime
dependencies. Do not depend on a developer's absolute paths.

## Protocol

Emit one UTF-8 JSONL `ready` event at startup. Read requests from stdin and write
responses to stdout; diagnostic logs belong on stderr. The message limit is
1,500,000 bytes. Stdout must never contain SDK banners or debug messages.

```json
{"event":"ready","protocolVersion":1,"adapterId":"my-device","modelId":"my-model","layout":{"width":112,"height":112,"rotation":0,"keys":[{"id":"key:0","rect":[0,0,112,112],"sourceWidth":72,"sourceHeight":72}]},"capabilities":{"fullFrameOnly":true,"width":112,"height":112,"format":"jpeg"}}
{"id":1,"method":"discover","params":{}}
{"id":1,"result":{"devices":[{"id":"stable-usb-id","adapterId":"my-device","modelId":"my-model","displayName":"My Device","capabilities":{"keys":1,"dials":0,"displays":[{"id":"key:0","width":72,"height":72,"format":"jpeg","partial":false},{"id":"lcd","width":112,"height":112,"format":"jpeg","partial":false}]}}]}}
```

| Method | Required behavior |
| --- | --- |
| `describe` | Return static layout and capabilities without opening USB. |
| `discover` | Return only supported devices, with IDs stable across restarts. Avoid initialization writes. |
| `open` | Select `deviceId`, report actual firmware and compatibility warnings, and bind `sessionId` and `generation`. |
| `frame` | Accept `{jpeg,width,height}` containing one complete baseline RGB JPEG. |
| `control` | Apply supported volatile brightness/sleep/wake controls; reject unsupported commands. |
| `close` | Release native handles and ownership, then return `{status:"closed"}`. |

Replies are `{id,result}` or `{id,error:{code,message}}`. Release native resources
on stdin EOF as well. The parent enforces bounded shutdown and terminates workers
that do not exit. Reject requests for stale sessions or other devices.

`rect` is `[x,y,width,height]` in the composed canvas. Rectangles must fit and
must not overlap. `sourceWidth` and `sourceHeight` describe logical host images.
For a continuous touch strip, add `layout.strip` with
`x,y,width,height,logicalWidth,logicalHeight`; omit it when absent.

## Display and input

The core composes keys, strip, background and screensaver before submitting a
frame. It applies the declared wire `rotation`; do not rotate the frame again.
Send the complete image directly when hardware supports it. Otherwise, declare
an explicit compatibility mode, such as `hardwareFullFrame:false` and
`usbOutput:"compatibility-regions"`, and split the canvas inside the adapter.
Device-specific cropping must not leak into the core or GUI.

Keep at most one transfer in flight and discard obsolete pending frames. Skip
unchanged regions if useful, but invalidate hardware caches on wake/reconnect.
Never use persistent background uploads, firmware flashing or persistent settings
writes as a streaming path. Submission success is not LCD display readback.

```json
{"event":"input","deviceId":"stable-usb-id","sessionId":"current-session","generation":1,"sequence":1,"type":"key","index":0,"state":"down"}
```

Use increasing session-local `sequence` values and zero-based indices. Dial
rotation uses `type:"dial",kind:"rotate",index,delta`; a click may use
`kind:"pulse"`. Touch uses logical strip coordinates, for example
`type:"touch",gesture:"tap",x,y`; swipes also include `endX,endY`.
Declare synthesized down/up pulses honestly; they do not establish physical
release, hold or press-and-turn support.

## Package and install

Place the executable and dependencies in a package directory. Use the manifests
generated by `scripts/stream-dog/stage.mjs` as working metadata examples:

- `id`, `name`, `version`, `license`, `platforms`, `architectures`.
- `entry.command`: a relative executable, or `@runtime/node` with the script in
  `args`. `${root}/file` resolves inside the installed package.
- `hostTarget`: a public SDK target with displays, logical geometry and virtual
  product configuration. Reuse a supported host target or verify host acceptance
  separately. Arbitrary geometry/product IDs are not automatically supported.

The manager supplies persisted dock/child serials and MAC addresses per device.
Do not hardcode a shared virtual identity.

```powershell
node scripts/stream-dog/create-adapter-manifest.mjs metadata.json work/my-pack
node scripts/stream-dog/pack-adapter.mjs work/my-pack dist/MyDevice-0.1.0.hga
```

The first command adds schema/protocol metadata and the complete SHA-256 file
inventory to `adapter.json`. The second validates and creates the ZIP-based
`.hga`. Path traversal, special files, missing dependencies and hash mismatches
are rejected. Keep an installed package immutable; changed files require a new
registration.

In Adapter Management, choose Add `.hga`, review external-code warnings and DLLs,
then confirm installation. Registration validates without executing the adapter;
discovery runs it. Only the verified application's bundle inventory establishes
official provenance. Hash checks establish integrity, not malware safety;
obfuscated or packed DLLs cannot be established safe by these checks.

Before sharing, test discovery, selection, full-frame output, input, disconnect,
EOF and crash cleanup. Check independent identities and disconnect behavior with
two sessions. Physical checks must cover layout, orientation, all controls,
screensaver restoration, USB reconnect and host restart. Publish exact model,
VID/PID, firmware, license and verification limits. Simulation success cannot be
reported as physical-device verification. See the [hardware recipe](../compatibility/hardware-testing.md).
