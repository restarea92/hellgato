# Stream Deck startup preparation

`version.dll` is an x64, static CRT proxy for the 17 system VERSION exports. It activates only in `StreamDeck.exe`. The fixture host is enabled only in the separate test build. `HellgatoStartupIdentity` identifies the proxy with `Hellgato.Startup.VERSION/1`.

`DllMain` installs a one-byte entrypoint breakpoint and a vectored exception handler. Plan parsing, executable hashing, allocations, and code preparation run when that entrypoint executes, after the loader releases its lock. `HellgatoStartup.plan` resides beside the DLL. Its schema is generated by `host-integrations/streamdeck/windows/python/hellgato_host/startup_plan.py`; executable SHA-256, PE metadata, every guard, and every original patch site must match before code changes begin.

The second breakpoint intercepts the model initializer's call to `_Init_thread_footer`, while its guard is still `-1`. A bounded private-memory scan finds the unique `20GBD9901` descriptor. The original two controllers, eight coordinates, encoder strip, and process-heap allocation must match. Preparation allocates ten coordinates with `HeapAlloc`, preserves the old allocation, and replaces the key width and vector before the original footer publishes the model. This changes the shared Plus model; simultaneous use with a genuine Stream Deck + remains outside this beta's tested scope.

The 56-byte, schema-1 mapping `Local\Hellgato.Startup.<pid>` records process identity, creation time, state, error, image base, feedback allocation, and descriptor address. State is published last: `1` preparing, `2` ready, `3` incompatible, or `4` error. The mapping, feedback allocation, and replaced vector remain valid until process exit. Validation failures restore the original code and descriptor before allowing normal execution to continue. The DLL never launches, restarts, or terminates the host.

Build with MSVC x64 and the Windows SDK:

```powershell
python -B host-integrations/streamdeck/windows/native/startup/build.py --test
```

The production artifact is `work/build-native-startup/version.dll`. The isolated synthetic host checks preparation before footer publication, all 17 VERSION exports by name and ordinal, the three APIs imported by Stream Deck, process identity, missing or malformed plans, hash and guard mismatches, invalid model rejection, and rollback after descriptor mutation. Results are written to `work/build-native-startup/fixture/fixture-results.json`. These tests do not establish hardware behavior in Stream Deck.
